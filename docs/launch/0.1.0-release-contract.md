# Elattar 0.1.0 release contract

`0.1.0` is the first release we will actively recommend for real application
work. It is a milestone, not a date. The version moves only when every item
below has evidence.

## Promise

> Production-ready Flutter components delivered as source you own—accessible,
> customizable, and AI-ready.

The release guarantees a stable CLI command surface and registry schema for the
rest of the `0.1.x` line. Component source can continue to evolve because the
installer copies versioned files into the consumer's project and never changes
them silently.

## Exit criteria

- [ ] `dart pub publish --dry-run` reports no warnings for `elattar_cli`.
- [ ] pub.dev reports 160/160 points: public API documented, package example
      present, analysis clean, and dependencies current.
- [ ] A fresh Flutter project passes `init`, installs three representative
      components and `agent-console`, then passes `flutter analyze` and
      `flutter test` on Windows and Ubuntu.
- [ ] The current registry validates, is reproducible, and has a released
      immutability snapshot.
- [ ] The documentation site builds at its production origin and every install
      command resolves to the release being described.
- [ ] The landing page survives 390 and 1440 logical-pixel widths, light and
      dark themes, 100% and 200% text scale.
- [ ] Three people outside the maintainer's environment complete the
      quickstart without live help. Their friction and resulting fixes are
      recorded below.
- [ ] `CHANGELOG.md`, `packages/elattar_cli/CHANGELOG.md`, release notes, tag,
      CLI identity, registry version, and documentation release facts all say
      `0.1.0`.
- [ ] Known limitations name the minimum supported Flutter version, package
      foundation mode status, and the overwrite/migration contract.

## Release sequence

1. Close every exit criterion on a release branch.
2. Run the complete repository verification ladder.
3. Bump the registry and CLI with the tools documented in `tool/README.md`.
4. Publish `elattar_cli` and confirm its live pub.dev page and score.
5. Tag and create the GitHub release from the same verified commit.
6. Deploy the site and verify `/registry/0.1.0/` without modifying prior paths.
7. Publish the launch material only after the install command works anonymously.

## Rollback

A published Dart package version and registry path are immutable. If a release
is faulty, mark the package version retracted on pub.dev, document the reason,
fix forward with a new patch version, and leave the original registry bytes
unchanged.
