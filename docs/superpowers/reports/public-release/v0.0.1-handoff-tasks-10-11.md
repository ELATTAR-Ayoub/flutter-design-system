## 2. Task 10 — harden CI

Plan section: **Task 10**. Read it; this section only adds what the plan
cannot know.

### What CI does today

`.github/workflows/ci.yml` is a single Ubuntu job on `pull_request` and
`workflow_dispatch`. It runs root analyze/test, CLI format/analyze/test,
registry build **and validate**, example analyze/test, and one web build.

### What is missing, and why each one matters

1. **No push trigger.** The commit that gets tagged has never been through the
   pipeline. Add `push` on `main` and on `public-release-v0.0.1`, plus manual
   dispatch.
2. **No registry reproducibility gate.** CI rebuilds the registry and
   validates it, then throws the result away. A PR that changes a distributed
   source without rebuilding passes clean, and the committed registry ships
   hashes that no longer match their files. Add
   `git diff --exit-code -- registry/generated/latest registry/component_inventory.json`
   immediately after the build.
3. **No publish dry run.** `dart pub publish --dry-run` in
   `packages/elattar_cli` is currently 0 warnings. Keep it that way by
   running it. Note it warns on a dirty git tree, so it belongs after
   checkout and before anything that writes.
4. **Format is checked on the CLI only.** Root, example and the three tool
   packages are unchecked. See §4 for why the tool packages need their own
   invocation.
5. **Linux only**, for a CLI built around Windows path handling. The plan's
   shape is right: a **CLI-only** Windows/Ubuntu matrix, not the full Flutter
   suite twice.
6. **`tool/registry_builder`, `tool/release_registry` and
   `tool/generate_perlin_texture` have tests that CI never runs.** All three
   are `dart test`, all three are fast.

### Also create

- `tool/release_audit/bin/verify.dart` plus focused tests. It does not exist
  yet. The plan's intent: one command that fails if any release invariant is
  broken — version identity across the six places it is stated, provenance
  hashes, no placeholder license, registry/index agreement.
- `.github/workflows/publish-cli.yml` — **only after** the first manual
  pub.dev publish, per the plan. Do not add it now.

### Residue to reconcile while you are in there

Shots were removed from the registry at `9c48294` and no `shot` item ships.
Two things still refer to them:

- `packages/elattar_cli/test/shot_install_test.dart` — passes, against a
  synthetic fixture rather than a real registry item.

Decide deliberately: either restore a real end-to-end consumer install as the

## 4. Repository-specific traps

Every one of these cost real time in Tasks 0–9. They are not in the plan.

### Testing

- **`pumpAndSettle` hangs on any page containing `Alert`.** `Alert`
  renders `BloomCosmic`, whose controllers `repeat(reverse: true)` forever.
  Use `tester.pump()`. `example/test/components_docs/alert_test.dart` says so
  at the top of the file; the error-state tests in `registry_docs_test.dart`
  and `changelog_docs_test.dart` follow the same rule.
- **`AssetBundle.loadString` hands anything over 50 KB to `compute`**, and
  that isolate never completes under the test binding. The symptom is a
  ten-minute timeout, not a failure. `registry_document.dart` loads bytes and
  decodes them for exactly this reason. If you add an asset read, do the same.
- **`Directory.current` is process-wide, and `dart test` runs test files in
  separate isolates of one process.** Setting it in one suite reaches into
  every other suite running concurrently. `ElattarCli` takes a
  `workingDirectory` seam; use it rather than mutating the global.
- **Tests that assert a temporary limitation become its enforcer.** This has
  now happened twice in this repository — nine component-doc tests required
  the pages to say components were uninstallable, and three route tests
  required three declared routes to be absent from the sidebar. Both sets were
  correct when written. If you write "asserts X is not yet supported", tie it
  to the fact that makes it true, or expect to be the one inverting it.

### Line endings and hashes

- `.gitattributes` pins everything to LF. This is load-bearing: the generated
  registry records a sha256 per distributed file computed from the **working
  tree**, and before the pin, 51 of the 112 files hashed differently per
  operating system. Do not weaken it, and be suspicious of any hash mismatch
  that appears only on one platform in the new Windows matrix.

### Analysis and formatting

- The root `analysis_options.yaml` **excludes** `tool/registry_builder/**`,
  `tool/release_registry/**`, `tool/generate_perlin_texture/**` and four
  tests that import across package boundaries. Those packages have their own
  `dart analyze` and `dart test`; CI must invoke them separately or they are
  checked by nothing.
- `tool/generate_icons.mjs` runs `dart format` on its own output. Without
  that, regenerating turned a 52-line header change into a 21,000-line diff of
  pure line-breaking churn. Do not undo it.

### The CLI

- `dart pub publish --dry-run` warns on a dirty git tree. Commit first, or the
  warning count is not the packaging signal you think it is.
- `packages/elattar_cli/.pubignore` excludes `test/` deliberately: the suites
  serve `../../registry/generated/latest` and compare against the repository
  LICENSE, neither of which exists inside the archive.

## 5. Boundaries

**Do not**, under any circumstances, without the owner saying so explicitly in
the conversation:

- change repository visibility,
- create or push any tag,
- deploy GitHub Pages,
- run `dart pub publish` without `--dry-run`,
- create a GitHub release.

Those are Task 12 and they belong to the owner. `.github/workflows/pages.yml`
is deliberately `workflow_dispatch`-only behind a gate comment naming what is
still open; leave it that way until Task 12 is done.

Work on `public-release-v0.0.1`. Do not create a `codex/`-prefixed branch.
