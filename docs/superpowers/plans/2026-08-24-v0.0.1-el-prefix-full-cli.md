## 1. Goal

Finish the unpublished `0.0.1` release with one coherent Elattar identity and
one complete source-first distribution path:

1. Standardize the maintained package, examples, tests, active documentation,
   skills, registry payloads, and CLI fixtures on the public Dart type prefix
   `El*`.
2. Keep the lowercase `el(...)` spacing-scale function. It describes the
   four-pixel design-system unit and is not a component identity prefix.
3. Rename the legacy rule file/slug to `validation_rule.dart` / `rule`, and rename
   `el_safe_area.dart` to `safe_area.dart`.
4. Account for every component library exported by
   `lib/elattar_design_system.dart` in an explicit registry distribution
   decision.
5. Make every user-facing component installable by slug and provide
   `elattar add --all` for a complete component installation.
6. Preserve runtime behavior, visuals, semantics, states, accessibility,
   responsive behavior, and motion. This is an API/distribution migration,
   not a redesign.

## 2. Locked decisions and one naming boundary

### Locked

- The Flutter package under `lib/` remains authoritative.
- This is a hard pre-release rename. Do not leave deprecated legacy aliases in
  the public API.
- The release remains `0.0.1`; there is no published consumer contract to
  preserve yet.
- Package components continue to live in `lib/src/components/`.
- CLI-installed components continue to live in `lib/components/ui/` in a
  consumer project.
- Registry manifests remain curated metadata. Automation may discover imports,
  exports, hashes, and missing decisions, but it must not invent semantic
  dependencies, descriptions, assets, shaders, or documentation routes.
- Existing component states remain unchanged: normal, loading, empty, error,
  success, disabled, focus, selected, reduced-motion, and recovery behavior.
- Existing visual behavior remains unchanged in light/dark and narrow/wide
  layouts.

### Naming boundary

| Current | Final | Reason |
| --- | --- | --- |
| `Button`, `Theme`, `Type`, `Press` | `Button`, `Theme`, `Type`, `Press` | Elattar-owned public API |
| `el(...)` | unchanged | spacing-scale function, not a component prefix |
| `validation_rule.dart`, `rule` | `validation_rule.dart`, `rule` | remove brand leakage from file and CLI slug |
| `el_safe_area.dart` | `safe_area.dart` | remove brand leakage from file name |
| suffixed wordmark | `ELATTAR` | avoid retaining the rejected suffix in current product copy |

Historical Git commits preserve the old naming decision. Maintained source and
current documentation should describe only the final `El*` API.

`component_inventory.json` is the completeness boundary. Every component
library exported by the package barrel must have exactly one decision:

- `installable`: its own user-facing CLI item;
- `dependency`: an internal item installed transitively; or
- `bundled`: copied as part of a named parent item such as `chart` or `icon`.

The final number of component manifests must be derived from this inventory,
not asserted from the current file count. The acceptance criterion is zero
unclassified exported libraries, not an arbitrary manifest total.

## 7. Commit and review boundaries

Use small commits so any failed wave can be reverted without touching unrelated
work:

1. `test(api): inventory El prefix and registry coverage`
2. `refactor(api): rename public types to El`
3. `docs(api): migrate examples, docs, and skill contract`
4. `feat(registry): cover complete component inventory`
5. `fix(registry): make generated output clean and deterministic`
6. `feat(cli): install all components with --all`
7. `test(cli): verify shipped full-registry consumer install`
8. `docs(release): record v0.0.1 migration and verification`

Do not mix the pre-existing docs rewrite into these commits unless Task 0
explicitly makes it part of the branch baseline.

## 8. Risks and controls

| Risk | Control |
| --- | --- |
| Bulk rename damages Dart identifiers or lowercase `el(...)` | token-aware mapping plus prefix guard and spacing tests |
| Existing docs work is overwritten | checkpoint before branch; preserve current diff; edit with patches |
| Generated icons restore legacy prefix | update generator before generated Dart |
| One file per manifest produces broken composite components | explicit bundled/dependency decisions |
| Import scan misses semantic or asset dependency | curated metadata remains authoritative |
| Stale payloads survive regeneration | validated temporary output and exact-directory replacement |
| Synthetic tests pass while shipped registry fails | fresh consumer verification against `generated/latest` |
| `--all` installs internal items as public choices | user-facing inventory flag plus dependency closure |
| Historical count or README drifts again | calculate/report from generated index in tests/docs tooling |
| Behavior changes during API rename | preserve assertions; representative visual diff; full suites |
