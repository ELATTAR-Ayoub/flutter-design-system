## 1. Goal

Ship the first genuinely public Elattar release with a shadcn-style
source-ownership model:

1. License Elattar's original work under the standard MIT License.
2. Preserve every third-party license and replace any asset whose provenance
   cannot be proven.
3. Make the GitHub repository, documentation site, and versioned registry
   publicly reachable.
4. Publish `elattar_cli` `0.0.1` to pub.dev so a new user can install the CLI
   without cloning this repository.
5. Make the installed CLI use a hosted, version-pinned registry by default,
   while retaining local registry overrides for contributors.
6. Harden CI around registry reproducibility, CLI packaging, Windows paths,
   consumer installation, documentation, and release builds.
7. Make README and changelog statements match the shipped product.
8. Add complete public Typeset, Registry, and Changelog documentation pages.
9. Publish only after a clean external consumer can install, analyze, test, and
   build with the same artifacts a real user receives.

## 2. Locked decisions

### 2.1 License model

- Use the unmodified standard **MIT License**, matching shadcn/ui's repository
  license model.
- Recommended copyright line:
  `Copyright (c) 2026 Ayoub Elattar`.
- The owner must confirm the exact copyright-holder spelling before Task 1
  writes the license. That line is the only remaining owner-supplied legal
  value.
- MIT requires the copyright and permission notice to travel with copies or
  substantial portions. It does **not** require a visible “Built with Elattar”
  badge, a link in every application UI, or public marketing credit.
- Do not add a custom attribution clause to MIT. If visible in-product credit
  is mandatory, stop: that is a different license decision and is not the same
  model as shadcn/ui.
- Elattar's MIT license does not replace licenses for fonts, Lucide geometry,
  the vendored shader, or any other third-party material.

This plan is an engineering release plan, not legal advice. The implementation
agent may reproduce verified upstream license texts but must not invent,
summarize, or rewrite their legal terms.

### 2.2 Distribution model

- Publish `packages/elattar_cli` as `elattar_cli` `0.0.1` on pub.dev.
- Keep root `elattar_design_system` at `publish_to: none` for `0.0.1`. The root
  package remains the authoritative repository implementation and is usable
  from public Git, but the consumer product is source installation through the
  CLI.
- Keep `--foundation source` as the supported public path.
- Keep package foundation mode rejected until a real, separately designed and
  published foundation package exists. Do not resurrect the nonexistent
  `elattar_core` dependency.
- Host the generated registry at a same-origin GitHub Pages path:
  `https://elattar-ayoub.github.io/flutter-design-system/registry/0.0.1/`.
- CLI `0.0.1` pins that versioned URL. A mutable `/registry/latest/` alias may
  exist for browsing, but a released CLI must not silently move to it.
- `--registry PATH_OR_URL` remains the explicit override for repository work,
  mirrors, and tests.

### 2.3 Documentation and UI contract

- The Flutter package remains authoritative. Public docs import only
  `package:elattar_design_system/elattar_design_system.dart`.
- Product documentation stays under `example/lib/`, never
  `lib/src/components/`.
- New pages use `Text`/`Type`, `Theme`, `el(...)`, `Widths`,
  `Breakpoints`, `Containers`, semantic components, `Durations`, and
  `Curves`. No hardcoded color, typography, geometry, surface, or motion
  values may enter `lib/` or `example/lib/`.
- The new docs pages share the current `DocsLayout`, sidebar, search, pager,
  breadcrumb, code, and fact-table contracts.
- Visual direction: a restrained editorial specimen sheet. Live content owns
  the hierarchy; neutral surfaces structure it; action color identifies links
  and copyable code; no new decorative effect competes with the content.
- Supported forms: narrow/mobile, tablet, and wide desktop; light and dark;
  keyboard and pointer; text scaling; reduced motion.

## 3. Baseline and known gaps

At `ced1b4d`:

- The worktree is clean on `public-release-v0.0.1`.
- The CLI and registry implementation exists and the source-first consumer
  workflow has been verified locally.
- `packages/elattar_cli/pubspec.yaml` contains `publish_to: none`.
- The CLI package has no package-local `README.md`, `CHANGELOG.md`, `LICENSE`,
  or `.pubignore`.
- The root `LICENSE` is the literal placeholder `TODO: Add your license here.`
- The unauthenticated GitHub API cannot see the repository; public users cannot
  clone it yet.
- `elattar_cli` has no pub.dev package record as of 2026-08-24. Availability is
  not guaranteed until the first publish succeeds.
- `RegistryClient.remote` exists, but the command application deliberately
  rejects URLs and only discovers a local `registry/generated/latest`.
- The default cache is memory-only, so it does not support useful offline work
  across CLI invocations.
- CI is Linux-only, lacks a registry `git diff --exit-code` reproducibility
  gate, and does not run on pushes.
- Pages deployment is manual and correctly blocked by the old release audit.
- `docs_pages/catalog.dart` declares Typeset, Registry, and Changelog routes,
  but `site_routes.dart` and `main.dart` intentionally do not route them.
- The old `/design-system/typography` page renders Inter but still tells users
  that the word face is Space Grotesk.
- README and CHANGELOG contain stale “private/unpublished” statements and
  historical test/registry totals.

Before editing, the implementation agent must re-run this baseline rather than
assuming every older Phase I finding remains open. Several consumer mechanics
were already fixed after that audit.

## 4. Target architecture

```text
pub.dev
└── elattar_cli 0.0.1
    ├── bin/elattar.dart
    ├── lib/
    ├── README.md
    ├── CHANGELOG.md
    └── LICENSE                         # Elattar MIT

GitHub Pages
└── flutter-design-system/
    ├── index.html + Flutter docs app
    └── registry/
        ├── 0.0.1/                      # immutable release registry
        │   ├── index.json
        │   ├── registry.json
        │   └── versions/**
        └── latest/                     # optional browsing alias

Consumer Flutter app
├── elattar.yaml                        # pins the versioned registry URL
├── .elattar/manifest.json              # installed-file ledger and hashes
├── LICENSES/
│   ├── ELATTAR-MIT.txt
│   ├── Inter-OFL-1.1.txt
│   ├── Geist-Mono-OFL-1.1.txt
│   ├── Redaction-OFL-1.1.txt
│   ├── Lucide-ISC.txt
│   └── ElevenLabs-UI-MIT.txt           # only when relevant payload ships
├── lib/components/ui/**
├── lib/design_system/**
└── assets/elattar/**
```

The license installer must be dependency-aware: `init` always installs the
Elattar MIT notice; the source foundation installs font notices; `icon`
installs the Lucide notice; `voice-indicator` installs the shader notice. Re-running
must be idempotent, and `--overwrite` must not silently delete unrelated
consumer license files.

### Task 12 — Publish in an irreversible-safe order

The implementation agent prepares every artifact but must pause at each
external owner gate.

1. Merge or fast-forward only the reviewed commits into
   `public-release-v0.0.1`; require clean CI.
2. Owner confirms the MIT copyright line and repository visibility change.
3. Make the GitHub repository public.
4. After a final package-name availability check and explicit owner approval,
   create and push the immutable `v0.0.1` tag from the CI-green commit.
5. Deploy docs plus the immutable `registry/0.0.1/` endpoint from that tag.
6. Run unauthenticated HTTP and clean-cache CLI smoke tests against that live
   endpoint.
7. Run and review the final CLI `dart pub publish --dry-run` archive.
8. Owner explicitly authorizes the irreversible first pub.dev publication.
9. Publish `elattar_cli` `0.0.1` from `packages/elattar_cli/` using the owner's
   authenticated pub.dev account.
10. From a clean environment, run `dart install elattar_cli`, then the complete
   public quickstart and consumer analysis/test/build.
11. Create the GitHub release from the authoritative changelog and the already
    verified `v0.0.1` tag.
12. Enable the reviewed automatic Pages trigger and configure future pub.dev
    automated publishing.

Do not publish the CLI before the versioned registry endpoint is live: an
installable command that cannot retrieve its payload is not a usable release.
Do not force-push or replace a published pub.dev version.

## 7. Risks and controls

| Risk | Control |
| --- | --- |
| MIT is described as mandatory visible attribution | State the real MIT notice condition; no custom clause |
| Elattar MIT is mistaken for permission to redistribute third-party files | Separate provenance ledger and exact upstream license texts |
| Unknown texture provenance survives | Deterministic replacement plus visual/performance review |
| Published CLI still needs a clone | Versioned hosted registry is live before pub.dev publication |
| Mutable registry breaks old CLI versions | CLI pins `/registry/0.0.1/`; immutable overwrite guard |
| Network error corrupts installation | Download/verify before mutation; atomic cache and installer writes |
| Offline flag is cosmetic | Persistent cross-process cache tests and clean cache-miss test |
| README command works only inside monorepo | Isolated package archive and unauthenticated live-endpoint smoke test |
| Version duplicated across CLI/registry/docs drifts | Version identity test and release audit |
| Registry generator passes with uncommitted drift | Build followed by `git diff --exit-code` |
| Windows path behavior regresses | Focused Ubuntu/Windows CLI matrix, not duplicated full Flutter suite |
| Flutter checks consume excessive time | Focused tests per task; full root/example/build once at final gate |
| Changelog page becomes a copied second source | Bundle and parse root `CHANGELOG.md` |
| Registry/docs counts become stale prose | Read generated JSON at runtime/test time |
| New docs create a parallel visual system | Repository UI skill, public El APIs, token guard, light/dark narrow/wide review |
| Three declared docs routes remain partial | Catalog-to-builder/sidebar/search completeness test |
| Publication is irreversible | Dry-run, archive inspection, live registry smoke, explicit owner approval |
