## 1. The one rule (RULES §0; AGENTS.md; README)

**Nothing is hardcoded. Everything comes from the system.** No hex, no `rgba()`, no `text-[13px]`, no `tracking-[0.1em]`, no `rounded-[14px]`, no `duration-[220ms]` — anywhere except `app/globals.css` (§6). Colour, typography, radius, spacing, motion all come from tokens; exactly one scale per axis. Enforced by `npm run check:tokens`; RULES §10.5 calls this rule "the system" itself.

## 2. Colour (RULES §1)

**Complete token inventory ("Nothing else exists"):**
- Monochrome (zinc): `--background` `--card` `--muted` `--accent` `--foreground` `--muted-foreground`
- Action ×3 + ink: `--color-action-bright` `--color-action` (fill) `--color-action-dark` `--color-action-ink` (text, per theme)
- Value ×3 + ink: `--color-value-bright` `--color-value` `--color-value-dark` `--color-value-ink`
- State ×4 + ink: `--color-success` `--color-warning` `--color-info` `--destructive`, each with an `-ink` shade that flips per theme

**Ramps named for role, not hue** — action is blue today, value is lime; formerly purple-and-gold and wine-and-amethyst. `bg-action` survives a rebrand; `bg-purple` would not. Rebrand = editing token values in `globals.css` only (README: "not a sweep through seven hundred class names").

**Neutral is zinc under the blue**; all chroma belongs to the two ramps + four state hues (70/20/10 balance). A chromatic neutral is possible but every surface pair must be re-measured; `--muted-foreground` breaks first.

**Page light source**: `body` carries one wide off-centre radial lift over `--background` (`--page-glow`), fixed to the viewport, fading to `transparent` (vignette = absence of glow, prevents muddiness).

**Rules §1.1–1.7:**
1. **One vocabulary, shadcn's**: page `--background`, container `--card`, fill `--muted`, hover surface `--accent`, text `--foreground`/`--muted-foreground`, hairlines `--border`/`--input`. Never invent parallel names.
2. **Action acts, value pays.** Action = buttons, selection, active nav, focus, the agent. Value = balances, rewards, rankings, premium actions. Never swap. Prose calls them blue/lime; code calls them action/value.
3. **Only `-ink` carries text, and it differs per theme.** Dark: `--color-action-ink` → `--color-action-bright`; Light: → `--color-action-dark`. `text-action-ink`/`text-value-ink` are the ONLY brand-text utilities; `text-action-bright` is banned. Mid shade fills a button and takes `text-primary-foreground`. `--ring` takes whichever end clears 3:1 per theme. **State colours are on the same contract**: write `text-destructive-ink`/`text-success-ink`/`text-warning-ink`/`text-info-ink`, never the raw token (`--destructive` is one red both themes; `--color-warning` 1.67:1 and `--color-info` 1.81:1 on white). Each `-ink` IS its raw token in the theme it was chosen for — swap costs nothing; no legitimate exception known or claimed. **A mark with no foreground of its own is on the same contract as text** (progress fill, slider range, 2px tab rule — visible only by contrast with `--muted`): measured `--primary` 3.25:1 dark / 4.17:1 light on `--muted` vs `--action-ink` 8.05:1 / 9.62:1; on the wine palette `--primary` was 1.63:1 (invisible progress bar), so thin marks use `bg-action-ink`, and `Progress` state tones use `bg-success-ink`/`-warning-ink`/`-destructive-ink` (raw `--color-success` on light `--muted` is 2.31:1; `bg-success-ink` 4.99:1). Filled `Tabs` pill and checked `Checkbox` keep `bg-primary` (they carry a foreground). **`--chart-1..5` are on this rule too and it reordered them**: each chart token names the end of its ramp that reads in this theme, two state hues fill the tail; all twenty pairs measure 4.58:1–17.04:1 on `--card`/`--background` against a 3:1 floor (wine palette had failed at 2.01/1.44/1.69). Fills/borders/rings/blooms keep the raw token (`bg-destructive/12`, `[--bloom-1:var(--color-success)]` correct). Guard covers class spelling everywhere except `globals.css`, and declaration spelling (`color: var(--color-warning)`) **everywhere including `globals.css`**. **Blind spot: `fill:`/`stroke:`** — checked by eye and measurement, not by the guard.
4. **Money out is not red.** Red = error. Outgoing money: plain text + sign + outgoing arrow. Money in: **value ramp** (not `success` — §1.5 keeps completed ≠ valuable). `Stat` delta is the one exception, uses `success-ink` (direction, not amount). A falling metric is never `--destructive`. **But a figure outside its band may be red** — test: would it be flagged if it had not moved? Yes → band, `destructive` available; no → delta, red wrong. Metric cards encode three named levels, never a free `tone` prop.
5. **State colour must not collide with a brand ramp** — working clearance ~**40°**. `info` moved to cyan (was blue 400, collided with action); `success` is deeper emerald (was green 400, ~lime); `warning` amber unchanged (40° off lime, 143° off blue). `destructive` clear of blue by 158° — property of this palette, not of the rule; a red-family rebrand must rebuild the reasoning and §7's two-non-colour-signals rule becomes load-bearing.
6. **Never Tailwind stock `blue-*`, `lime-*`, `purple-*`** — all three namespaces cleared in `globals.css` (second lock; `check:tokens` `stock-palette` rejects every Tailwind hue regardless). On rebrand, move the clears to the new hues.
7. **Two complete themes, dark default.** `next-themes` sets `.dark` on `<html>`; `:root` is light; dark is what a first-time visitor sees.

**What light mode costs (§1, all handled in `globals.css`, no component `dark:` variants):**
- **Shadow ink** via `--ink-1..4`, `--rim`, `--wall`: dark = black ~60%; light = slate-tinted ink at ~a fifth the opacity. Chromatic neutral would need both inks re-tinted.
- **Rim inverts**: dark = white inner top highlight; light = bottom inner shade shapes instead.
- **`mix-blend-mode: screen` → `multiply`** (cosmic bloom, action sheen flip; foil doesn't — own opaque base).
- **Light `--muted-foreground` chosen by measurement, one step deeper than zinc 500** (the "longest-standing measurement bug": zinc 500 `#71717a` was 4.83:1 on white but **4.40:1** on `--muted` `#f4f4f5`, a 0.10 AA miss). Now: light 6.04:1/`--background`, 5.50:1/`--muted`; dark 13.46:1, 10.08:1 — all four clear AA. ⚠ **Drift**: `RULES §5` Sidebar rule 3 still says `--muted-foreground` is "already the lightest step clearing AA on both `--background` and `--muted`" — the exact overstated claim §1 corrects.
- README addendum: a handful of `dark:` variants survive in vendored shadcn for one-off opacity tweaks (`dark:bg-input/30`) — harmless, not a pattern. **"If a colour needs `dark:`, the token is wrong."**

## 3. Typography (RULES §2; README hard-rule 5)

**Two faces**: words = Space Grotesk via `.type-*`; numerical values = **Geist Mono** via `.type-num-*` (class owns face + tabular alignment + weight + size together); serials `.type-serial`; code/token notation `.type-code`. **Geist Mono comes from Vercel's self-hosted `geist/font/mono` package, NOT Google Fonts** (canonical glyph set, font-features, no network substitute).

Scale (name → px): words `.type-display .type-h1 .type-h2 .type-h3 .type-h4 .type-lead .type-body .type-small`; nav/chips `.type-nav` 13.5 · `.type-chip` 11.5 · `.type-caption` 10.5 · `.type-code` 12.5; uppercase `.type-label` 11 · `.type-micro` 10.5 · `.type-badge` 11 · `.type-tag` 10; numeric `.type-num-xs` 11 · `.type-num-sm` 12 · `.type-num` 15 · `.type-num-md` 20 · `.type-num-lg` 28 · `.type-num-xl` 40.

Rules:
1. **Never hand-roll a size.** Every size also exists as `--text-*` token (`text-body`, `text-nav`…) for CVA strings. The live Typography page renders the actual classes and **must not restate px/weight/tracking in page copy** (values live only in `app/globals.css`). **`text-xs/sm/base/lg` are NOT violations** — `globals.css` repoints Tailwind's four steps at ours (`--text-sm` IS `--text-small`), which is what keeps sixty vendored shadcn components on the scale. Anything else needs a `.type-*` class. **"Legal is not the same as right"** — aliases carry size only; an element with a voice wants the full class (nav row → `.type-nav`). **A `.type-*` class cannot be reached through a variant** — they live in `@layer components`; `data-[size=md]:type-nav` compiles to nothing while guards stay green. Branch in TypeScript (`SidebarMenuSubButton` is the worked example).
2. **10.5px is the floor**, uppercase labels only.
3. **`.type-display` once per screen at most.**
4. **Tabular numerals everywhere money appears.**

## 4. Spacing, radius, elevation (RULES §3)

- **Spacing** — 8-point for **layout**: 4, 8, 12, 16, 24, 32, 40, 48, 64, 80. **Half-steps 2/6/10/14 (Tailwind 0.5/1.5/2.5/3.5) legal inside a component** (~100 uses). Line: separate things → scale; parts of one object → half-steps OK. **Finer than 2px is a mistake.** Stock-shadcn drift warning: stock menus `p-1`/`px-1.5 py-1`, tabs `p-[3px]`/`px-1.5 py-0.5` — none exist here. Every menu surface (dropdown, context, menubar, select, command) retuned to `p-2` container / `px-3 py-2` item / `gap-2` = 36px row. Tabs = 40px track, 4px inset, 32px triggers. **Re-running `npx shadcn add` brings cramped values back — diff before commit.**
- **Typography stacks declare their rhythm**: the owning component declares tokenized `gap-*`/`space-y-*`; never rely on line-height for separation; repeated stacks belong in the shared composition.
- **Native scrollbars use the global rail**: `html` automatic; nested overflow adds `scrollbar-thin`; both axes identical and token-driven; never hide a scrollbar that is the only more-content cue; `ScrollArea` only for composed application panels.
- **Pill padding**: radius = half height (40px control → 20px corner); content needs **16px** horizontal clearance (12 not enough); with an addon providing clearance, inner control drops to 8px.
- **Radius**: **controls are pills** (`rounded-pill`) — buttons, inputs, input groups, badges, chips. Containers ladder: `lg` 12 cards · `xl` 16 dialogs · `2xl` 20 · `3xl` 24. **Textarea exception** → `lg`. **`4xl` 32 off-ladder on purpose** — only a full-width slab on a narrow column (metric card on a glance column); never in a grid beside `lg` cards ("two container radii on one screen is drift").

**Shadows — two families** (ported from Yukirhythm; full page `/design-system/shadows`):
- Ambient: `shadow-e1`…`shadow-e4` (how far a surface floats).
- Machine: `shadow-btn` (secondary/outline/destructive) · `shadow-btn-primary` (primary, action cast) · `shadow-btn-value` (premium, value cast) · `shadow-btn-down` (`:active`, sinks) · `shadow-key`/`shadow-key-down` (raised key, side wall, 3px travel) · `shadow-pressed` (sunken socket, every input) · `shadow-chip` (raised but not pressable).
- **The rule: controls stand proud with inner top highlight; fields recessed.** Wrong way round = "flat cardboard".
- **Small solid shapes need a ramp**: every filled `Badge` variant carries `ramp-chip` + `shadow-chip`; unfilled variants (outline, ghost, link) get neither.

**Premium button foil (`foil-value`)** — three parts: (1) **ramp**: light–dark–light gradient with darker mid band = the metal's edge; **band depth is per-brand and must be re-measured on every rebrand** — 42% of `--color-value-dark` on lime (worst stop 7.80:1 vs foil ink; others 12.39/16.01/16.10); the same 42% on a low-luminance hue rasterised **4.11:1** and needed 30%. No guard can see it — pull stops from live `backgroundImage`, paint each into a 1×1 canvas (they're `color-mix(in oklab,…)`). (2) **foil** (`::after`): diagonal striations + broad sheen + warm top-left highlight, drifting on `soft-light` over 11s. (3) **glint** (`::before`): narrow bright band on `screen`, idles ~3.5s, sweeps ~1.6s, rests. Hover: glint 2.4s, foil to full opacity.

**Default button action sheen (`sheen-action`)** — quieter: (1) soft light–dark–light action-ramp; (2) `::after` striations + one diagonal sheen, **static**; (3) `::before` "beat": ellipse expanding from centre, strong beat + weaker echo + rest, **hover only**; press = single hard beat. Rationale: perpetual animation on a many-per-screen control would break §4.1. **CSS not canvas, deliberately**: a GPU surface on 130×40 renders at 64×19 — too few pixels; `screen` on value-over-value washes to white.

**Glow rationed**: `glow-action` = selected + primary CTA; `glow-value` = celebrated tiers + reward moments. **Navigation never glows.**

**Glass**: `glass-panel` and `glass-control` — translucent `--card`-held-back fill, hairline rim of the ink colour, `--rim-strong` top highlight; no `dark:` needed (mixed from `--card` + `--foreground`). **Split is scale, not taste**: panel blurs and floats; control only tints and rims (24px blur behind a 44px disc samples nothing; `--shadow-e2` under small controls = grime). **Blur must go through `@apply backdrop-blur-*`, never hand-written `backdrop-filter: blur(calc(var(--spacing) * 5))`** — the transformer silently dropped it (no error, both guards green); caught only via `getComputedStyle(card).backdropFilter === "none"`.

## 5. Motion (RULES §4)

**Motto: content bounces; controls click.** Never mix — "a button that jellies feels broken, a reward that clicks feels cheap."

- Durations (ms): `tick` **80** · `fast` 150 · `base` **250** · `slow` **400** · `overlay` 320 · `jelly` **420** · `reward` 550 · `bloom` **1000** (bloom = the atmospheric step, belongs to light).
- Easing: **`--ease-spring` `cubic-bezier(.34,1.56,.64,1)` is THE curve** (overshoot + settle) · `--ease-out` arrivals · `--ease-in-out` loops · `--ease-out-flex` long travel, no overshoot. ⚠ **Drift**: check-tokens' `arbitrary-easing` message additionally names `ease-settle` and `ease-standard`, which RULES §4 never lists.
- **Click feel: 40ms down, 250ms spring back** (asymmetry is the whole thing). Utilities: `click-spring` scale 0.9 (clickables that aren't Button) · `press-spring` 0.92 (larger surfaces) · `press-key` 3px linear (physical keys) · `lift` −3px + e3 (cards/tiles on hover). `Button` has the spring built in — never stack.
- **Selection travels, never blinks**: one pill physically slides and lands with a jelly squash via `useSlidingIndicator`; options never own selected backgrounds. Applies to `ToggleGroup`, `Tabs`, and anything alike. `Tabs` `line` variant travels a 2px rule filled `bg-action-ink` (not `bg-primary`, §1.3). Three traps: (a) **ordering** — an override cancelling a variant background must come **after** `toggleVariants()` in `cn()` (tailwind-merge keeps last); (b) **attribute** — Radix writes `data-state`, a sidebar row `data-active`; pass the attribute name, don't fake `data-state` (CollapsibleTrigger sets `data-state="open"` → pill chases disclosure); (c) **measurement** — position from the active element's rect, never `offsetLeft/Top` (relative to nearest positioned ancestor; broke silently in the sidebar where rows sit in `position:relative` list items).
- **One source of truth**: every keyframe in `app/globals.css` only; every animation exposed as one `.anim-*` class. One squash definition `.anim-jelly` shared by `IconSwap`, the sliding pill, `useReplayOnStateChange`. Only motion outside the system: `animate-spin` on the loading spinner. **Easing must be a `var(--ease-*)` token** — bare `ease-out` keyword or raw `cubic-bezier()` fails `check:tokens`; `linear` and `steps()` are fine.
- **Modals: `anim-jelly-in` / `anim-jelly-out` and nothing else** (`data-open:anim-jelly-in data-closed:anim-jelly-out`). In: `--duration-jelly` 420ms on `--ease-spring` (320 would clip the bounce). Out: `--duration-base` 250ms on `--ease-in-out` — **leaving is always faster than arriving**; the exit anticipates upward, then drops. Two fragile dependencies: keyframes drive **`transform` only, never `translate`** (dialog centring uses standalone `translate` property; violating it sends dialogs to the bottom-right); every `.anim-*` is registered with **`@utility`, not `@layer components`** (else `data-open:` variants compile to nothing).
- **Disclosure animates height**: Collapsible/Accordion via `anim-unfold` on `--ease-spring`, overshoots ~10% and settles (measured: 16 → 130 → **180** → 164 by 395ms on a 164px panel). `--unfold-h` indirection points at `--radix-collapsible-content-height` or `--radix-accordion-content-height`. **`overflow-hidden` is load-bearing.** Replaces tw-animate-css `accordion-down/up`.
- **Anchored overlays** (popover, tooltip, select, sheet, drawer, menus) keep their tw-animate-css fade/slide but are bridged by **one unlayered rule in `globals.css`** to `--duration-overlay` + `--ease-out` (else 150ms plain `ease`). The rule must be: on the animating element (vars are `inherits:false`), **unlayered** (Tailwind resets them in `@layer properties`), and a **substring attribute selector** (DOM class is `data-open:animate-in`). **Never pin `duration-*` on an overlay component** — eleven shipped with `duration-100` silently opting out.
- **Selection controls: recessed socket, raised knob.** Switch track `shadow-pressed` off / `shadow-btn-primary` on; thumb `shadow-btn`. Slider track = sunken channel filled `bg-action-ink`; thumbs raised. Sizes: 20px checkbox/radio/slider-thumb, 44×24 switch, 10px slider track (stock 16/12/4 too small). **The tick is drawn, not faded**: hand-authored path in `checkbox.tsx`, dash-offset to zero (`anim-check-draw`, `anim-dash-draw`, `anim-dot-pop`). **Every toggle squashes both directions** via `useReplayOnStateChange` (CSS can't: mount-fire + `:active` truncation; MutationObserver silent on first paint).
- **Two-state icon controls use `IconSwap`** (vertical strip, rolls up/down, arriving icon jelly-squashes; goes *inside* Button as child). `ToggleGroup` is for **3+** options; with two, use a toggle.
- **Timing declared in one `@utility`** — `btn-spring`, `swap-roll`, `press`, `click-spring`, `press-spring`, `press-key`, `lift`; never hand-assemble `transition-all duration-x ease-y` (order-dependent).
- **Discrete charts** (unit activity, conversion funnels) live in `components/el/charts`; marks only `--chart-1..5` (+ semantic `muted` remainder); values in `type-num-*`; specimens via `ChartStates`. Never redrawn in product pages.
- **JS-animating libraries read tokens, never copy them**: `components/el/chart-motion.ts` resolves `--duration-slow` off the live stylesheet, returns `isAnimationActive` from the reduced-motion media query. **A hardcoded `800` in a chart prop passes every guard and is still a §0 violation — "the guard is the enforcement, not the rule."** Recharts 3.8's `isAnimationActive:'auto'` honours reduced motion but stops the moment a boolean is passed, so the hook decides once. Easing curve can't be threaded (Recharts types 5 keywords); the keyword `ease-out` is passed as a *name* for the token, and the limit is documented in `chart-motion.ts` and on `/design-system/components/base/charts#animation` — "when a library will not take a token, say so where the next reader will look."
- **Named animations** (all `@utility`, all take variants): `anim-pop-in` (jelly pop from 25%) · `anim-jelly` · `anim-spring-up` · `anim-jelly-in`/`anim-jelly-out` · `anim-unfold`/`anim-fold` · `anim-ratchet` (stepped spin) · `anim-sign-on` (neon power-up, **text only**) · `anim-reveal` · `anim-shimmer` · `anim-pulse-live` · `anim-check-draw` · `anim-dash-draw` · `anim-dot-pop`. Plus `anim-swap-in` (named in §5 skeleton rule).
- Motion laws: (1) **only the live indicator and `bloom-cosmic` animate forever** (signal vs weather — 18s/11s counter-rotating drifts); (2) opening sequence always skippable from the start; (3) `prefers-reduced-motion` honoured globally — no information may exist only inside an animation; (4) never flash/strobe — `anim-sign-on` is the one flicker, runs once, text-only.

## 6. Components (RULES §5)

**Base `components/ui/*`**: sixty-odd shadcn primitives restyled **only** through the token layer; none forked for look. **Run `ls components/ui/` for the count — prose counts have drifted before.** Deliberate departures table: `Button` size ladder 32/40/48/56, `premium` value-foil variant, `emphasis="caps"`, `loading` · `Input`/`Textarea`/`InputGroup` 40px, 10px radius, `bg-muted` fill · `Alert` +success/warning/info, one surface, signal in icon+bloom · `Badge` +action/premium/success/warning/info (listed twice in the table; second row: `ramp-chip` + `shadow-chip` on every filled variant, pill radius) · `useIsMobile` rewritten on `useSyncExternalStore` · `Dialog`/`AlertDialog`/`Sheet` three-zone banding, jelly in/out · `DialogContent variant="media"` full-bleed `DialogMedia` lead · `AlertDialogAction` defaults `variant="destructive"` · `Tabs` travelling pill, 40/4/32 vs stock 32/3/25 · `Progress` 10px sunken channel (Slider track minus thumb), `tone` for out-of-band readings · `Avatar` fallback/group-count text tracks circle size · `Collapsible`/`Accordion` height on spring · menus/`Select`/`Command` on the 8-point scale · `Toaster` follows `resolvedTheme`, styling in `.cn-toast`. **`destructive` is a tint, not a solid fill** (white on the red = 3:1, fails AA).

**Overlay anatomy**: Dialog/Sheet = header band · body · footer band; bands bleed to panel edge, `bg-muted/50`, closed by rules (`border-b` header / `border-t` footer); only the body is lit. **Alert Dialog bands the footer only** — header/title/description sit directly on the panel (the question IS the content; the footer is the decision). Media Dialog is an anatomy variant, not another modal — never for destructive confirmation. Close button lands ON the header band, centred on title; `data-close-button` published, header reserves `pr-12` only when present; alert dialog has no close button ("answered, not dismissed"). `DialogHeader` bleeds `-mx-4 -mt-4` (DialogContent carries padding); `SheetHeader` doesn't; `AlertDialogHeader` bleeds nowhere.

**Constrained actions / sidebars**: constrained labels truncate (`min-w-0 max-w-full`, words in `ButtonLabel` owning the ellipsis, full label via `Tooltip` on hover+focus; automatic on `AlertDialogAction`/`AlertDialogCancel`); never shorten a consequence for layout. Product sidebars use the complete Sidebar composition, never a private rail.

**Feedback matrix (reversible-or-not)**: just-did confirmation → **Toast**; task containing a choice → **Dialog**; irreversible → **AlertDialog**; persistent condition → **Alert**; nothing yet → **Empty** (always offers a way forward). Don't reach for AlertDialog when Dialog will do.

**Every action needs two signals** — control heard you + outcome worked (e.g. `IconSwap` to check + success toast). Don't add `press-spring` to a Button (double bounce). **Ship the failure path** (`navigator.clipboard` rejects on insecure origins/denied permission).

**Skeletons**: match footprint exactly (render the same component with content replaced); `Skeleton` renders `<div>` — pass **`as="span"`** inside `<p>` (invalid HTML passes every guard); swap is **one** event, `anim-swap-in` on arriving content (fade-out-then-fade-in reads as a glitch). Skeleton = shape known, spinner = unknown, progress = honest percentage.

**Disabled**: `disabled:opacity-45` (~3.2:1 light / 4.4:1 dark) is **fine** — WCAG 2.1 SC 1.4.3 exempts inactive components; must be distinct from enabled; adjacent helper/error/label still owes AA; do not raise the opacity.

**`Stat` delta — a shape before a hue**: three colour-free signals — glyph shape (↑/↓/–), written sign (`+`/`−`/none), visually hidden word ("Up"/"Down"/"No change"). Colour fourth and **not red/green**: favourable = `text-success-ink`, unfavourable = plain `text-foreground`. `betterWhen="up"|"down"` is required knowledge — default green-for-rising lies on churn/refund/latency. Specimen page re-renders the deltas under `grayscale` as proof.

**Toast `.cn-toast`**: all sonner styling overridden in one `globals.css` block. Selector repeats the class **three times** (0,3,0 beats sonner's `[data-sonner-toast][data-styled="true"]` 0,2,0). Toaster reads **`resolvedTheme`**, never `theme`. `ToastPreview` renders the real markup minus `data-sonner-toast`, shares `.cn-toast` (verified identical: width, padding, radius, size, colours, border, shadow, action button). ## 8. Accessibility contract (RULES §7)

- Focus always visible, never removed.
- Every text colour clears AA; the colours page **measures** live.
- Status and money direction: **≥2 non-colour signals** (glyph + label, never hue alone).
- Icon-only controls require `label` (Icon) or `aria-label` (Button).
- Errors ship `aria-invalid` + written `FieldError` + `aria-describedby`.
- Progress bars: `role="progressbar"` + real value label.
- Destructive actions: `AlertDialog`, consequence **in the button** ("Sell all for $2,481.00", not "Confirm").
- Swipe always has tap + keyboard fallback.
- **Hit targets ≥ 44px, one deliberate exception**: default Button is 40px (sits level with 40px Input); primary touch target → `size="lg"` 48px; icon-only never below 40px; 32px `size="sm"` only in toolbars, never alone as the main action.
- Nested controls (dismiss ✕ on alert, clear ✕ in input): visual size exempt, hit area not — restore with negative margin and **measure** (`-my-2` vs `-my-3` differ by 2px).

## 9. Content style (RULES §8)

Short, direct, confident: **Open Pack**, **Sell Selected**, **Request Withdrawal**, **Claim Reward**. Never: *Proceed*, *Continue Process*, *Execute*, *Submit Action*. Write the consequence into destructive buttons; phrase cancel as the safe choice ("Keep my cards", not "Cancel").

## 10. Verification (RULES §9; AGENTS.md; README)

`npm run verify` = **check:tokens → check:refs → typecheck → lint → build**, all five, every time — the floor, not the ceiling. Four failure classes a green build cannot see (all have shipped):
1. **Dead references** — Tailwind drops unknown classes silently; CSS drops declarations with undeclared `var()`. Shipped: `shadow-btn-lime` (token is `--shadow-btn-value`) left the premium button shadowless for weeks; `--color-foreground-subtle` never declared. **The built stylesheet is the only authority**: `npm run build && grep` in `.next/static/chunks/*.css`; emitted = alive; absent = dead OR never referenced — state which. `globals.css` is not the whole stylesheet: it imports `tailwindcss`, `tw-animate-css`, `shadcn/tailwind.css` — the last defines nine `@custom-variant`s (`data-open`/`-closed`/`-checked`/`-unchecked`/`-active` match both `data-state="…"` and bare attribute; `data-disabled` bare only; **`data-selected` is only `[data-selected="true"]`**; `data-horizontal`/`-vertical` match `data-orientation`), plus `scroll-fade-*`, `shimmer-*`, `no-scrollbar`; Tailwind v4 itself supplies `scrollbar-none`, `scrollbar-gutter-stable`, `scrollbar-thumb/track-*` (verified v4.3.3). A false dead-reference report costs more than a missed one. **Prose can put a class in the bundle**: Tailwind v4 scans tracked non-binary files, markdown included — `globals.css` carries `@source not "../**/*.md";` to keep *emitted* meaning *referenced from code*.
2. **Both themes in a real browser** — flip the toggle; **light is where the bugs live**; check every foreground/surface, shadows, blend modes (`screen` invisible on white). Screenshot both; if the pane can't composite, substitute structural proof (box heights, computed colours, `getAnimations()`, no horizontal overflow) and say you measured rather than looked.
3. **Contrast measured, not eyeballed** — `useContrast` hook (`components/el/token-swatch.tsx`, token names, live re-measures); rasterise a 1×1 canvas for real elements and anything `color-mix()`/blended (computes to `oklab()`; "a ratio in the millions means you parsed one as RGB"). Disabled exempt.
4. **Reduced motion** — turn it on and look; any keyframe ending at `opacity: 0` freezes to nothing.
Report honestly: distinguish measured from looked-at; name what you did not check; never state an uncomputed ratio.

### `scripts/check-tokens.mjs` — hardcoded values

### `scripts/check-refs.mjs` — references resolving to nothing
Same roots/extensions. Comments blanked preserving line numbers (prose about a dead token is not a use of it).
